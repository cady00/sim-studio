# 应点仿真（Ondot Sim）· UI/UX 设计系统与规范 v0.9

> 适用范围：应点仿真桌面端（英文 Ondot Sim。Windows，C++20 / Qt 6，OpenGL 通过 `IRenderer` 抽象）
> 目标用户：汽车产线仿真工程师（焊装 / 涂装 / 总装 / 动力总成）
> 界面语言：简体中文为主，可一键切换 English
> 设计视野：面向 2030 年前后的 AI 原生工业软件，同时保证今天就能用 Qt 做出来
> 配套文件：`RESEARCH_NOTES.md`（调研与来源）、`mockups/*.png`（高保真效果图）、`mockups/src/`（效果图 HTML/CSS 源与令牌 CSS）

---

## 0. 一句话愿景

**“把 PDPS 的工程深度、MCD 的机电一体化、Visual Components 的易用，装进 Figma/Linear 级别的交互和 Cursor 级别的 AI 协作里。”**

产品里每一个操作都能做到三件事：**看得见**（3D 中可视化预览），**说得清**（结构化命令 + 理由），**退得回**（一次撤销 / 检查点）。

## 1. 设计原则（10 条）

| # | 原则 | 含义 | 反例（行业现状） |
|---|------|------|------------------|
| P1 | **场景是主角** | 3D 视口占据最大面积，UI 以浮层、上下文工具栏、可折叠面板围绕视口，不让 Ribbon / 对话框遮住模型 | 多层模态对话框、视口只占 40% 面积 |
| P2 | **任务模式，而非功能菜单** | 六个任务模式（建模/运动学/逻辑/机器人/调试/虚拟调试）各自带最优面板布局与工具集，但数据模型只有一份 | 一个巨型 Ribbon，几十个 Tab |
| P3 | **键盘优先、搜索优先** | 所有命令都在命令面板（Ctrl+K）可搜索；常用操作有单键/组合键；菜单只是“发现入口” | 需要记住命令藏在哪个菜单 |
| P4 | **AI 默认关闭、本地优先、计划先行** | AI 只产出“结构化命令计划”，在沙盒中预演，可视化预览后由人确认；所有 AI 改动可一键整体撤销；不联网 | 黑箱自动修改、无撤销、云端上传 |
| P5 | **正常时安静，异常时醒目**（ISA-101） | 常态使用灰阶/品牌中性色；红/黄/绿等高饱和色只留给报警、近碰、限位、强制等异常 | 满屏彩色按钮与状态灯，报警淹没其中 |
| P6 | **直接操作 + 精确数值并存** | 任意可拖拽的东西（Gizmo、滑块、时间线块、路径点）同时可以在检查器里输入精确数值和单位表达式（如 `2340+120`） | 只能拖、或只能在对话框里填 |
| P7 | **因果可追溯** | 任何信号、报警、近碰都能“跳到原因”：信号 → 逻辑块 → 关节 → 3D 位置；时间线可回溯 | 报警只有文字，需要人工找对象 |
| P8 | **确定性与可复现** | 仿真步长、随机种子、PLC 同步模式在 UI 中显式可见；同一输入总得到同一结果，便于评审与回归 | 每次仿真节拍略有不同，无从解释 |
| P9 | **渐进披露** | 新手看到“推荐参数 + 引导”，专家可展开全部字段、表达式、Python | 所有字段平铺在一个对话框 |
| P10 | **性能是一种 UI** | 帧率、加载进度、LOD、后台任务显式展示；UI 线程绝不被仿真/导入阻塞，长任务可取消 | 导入时界面“无响应” |

## 2. 用户、场景与核心任务

### 2.1 角色
- **线体仿真工程师（主用户）**：每天 6–10 小时；做工位布局、机器人可达性、路径、干涉、节拍、虚拟调试。多显示器（常见 2×27"），高 DPI 笔记本 + 外接屏混用。
- **自动化 / PLC 工程师（次用户）**：主要用信号表、逻辑块、虚拟调试模式，与 TIA Portal / PLCSIM Advanced 联调。
- **评审者（项目经理、工艺、客户）**：只看/批注；需要“演示模式”、节拍报表、录屏。
- **设备建模者**：用运动学编辑器从 STEP 构建自定义设备（夹具、变位机、滑台、升降机），没有预置组件库可依赖，所以建模效率是关键体验。

### 2.2 高频任务（按频率）
1. 导入 STEP → 简化 → 摆放 → 建立坐标系
2. 定义运动学（连杆/关节/姿态）→ 测试
3. 示教/编辑路径点 → 检查可达性、配置、奇异、限位 → 调节外部轴
4. 跑仿真 → 看碰撞/近碰 → 改
5. 编写逻辑块与信号 → 与 PLC 联调 → 看时序
6. 产出节拍甘特与报告

所有布局与快捷键设计都以这 6 条主线为优化对象。

## 3. 竞品痛点 → 设计对策（摘要，详见 RESEARCH_NOTES.md）

| 痛点（来源见调研） | 对策 |
|---|---|
| PDPS 大场景加载慢、仿真慢、UI 卡死（单线程，机器人程序循环可锁死 GUI） | 渲染/仿真/导入分线程；UI 永不阻塞；加载可渐进显示（先包围盒 → 低 LOD → 全精度）；所有长任务进“任务中心”可取消 |
| PDPS“必须先 Set Current Operation 才能在序列编辑器播放”，操作链路长 | 时间线自动跟随当前选择；“播放所选”一键；最近操作历史可钉住 |
| PDPS / MCD 学习曲线陡、文档分散、对话框多 | 命令面板 + 内嵌帮助卡；每个命令有“为什么/怎么用”的简短说明与示例；可选 AI 问答（本地文档索引） |
| MCD 物理场景复杂时性能差，需要手动简化碰撞体 | 导入时自动生成碰撞代理（凸包 / 简化网格），检查器显示“碰撞代理精度”，一键对比 |
| MCD 信号有两种类型（适配器信号 vs 全局信号）易混淆 | 单一信号模型：所有信号在信号表中统一显示，来源（逻辑块 / 设备 / PLC）只是属性 |
| Visual Components 依赖预置组件库，自定义设备建模门槛高 | 运动学编辑器作为一等公民：从几何直接“拾取轴”、链式可视化、姿态表、即时测试滑块 |
| 报警只有文本，排错靠人工 | “跳到原因”链；报警卡片带“定位/打开运动学/查看逻辑”动作 |
| AI 助手多为云端问答，不能直接执行、不可审计 | 本地结构化命令层；计划→预览→应用→撤销；活动记录与权限面板 |

## 4. 信息架构

### 4.1 统一对象模型（UI 视角）

```
项目 Project
└─ 站点 Station（可多个，工位/单元）
   ├─ 资源 Resources ── 机器人 / 外部轴 / 夹具 / 输送 / 自定义设备（运动学）/ 工具 TCP
   ├─ 工件 Parts ────── STEP 导入件、碰撞代理、材质
   ├─ 坐标系 Frames ─── 世界 / 基座 / 工件 / 工具 / 用户坐标
   ├─ 操作 Operations ─ 机器人程序（路径点 PTP/LIN/CIRC）、设备操作（姿态切换）、物流
   ├─ 逻辑块 Logic ──── 节点图（输入/输出/参数/条件/动作/定时器/子图）
   ├─ 信号 Signals ──── DI/DO/AI/AO/Int/Real，含 PLC 映射
   ├─ 脚本 Scripts ──── Python
   └─ 分析 Analyses ─── 碰撞集、近碰阈值、节拍、录像、快照
```

规则：
- **一个对象，到处可达**：装配树、3D、信号表、逻辑图、时间线中的同一对象共享选择状态（全局选择总线）。
- **对象都有“短名 + 类型图标 + 状态点”**，例如 `R01 · 6 轴机器人 ●`。
- **引用面板**：检查器底部显示“被谁使用 / 驱动谁”，以及 Python 访问路径（例：`cell.fx30.logic["夹紧序列"]`）。

### 4.2 导航层级
1. **任务模式**（标题栏中央分段控件，`1`–`6` 或 `Ctrl+1..6`）
2. **面板**（左：结构类；右：属性类；底：时间类；左侧图标栏切换面板）
3. **上下文**（浮动工具栏、右键径向菜单、检查器）
4. **全局**：命令面板 `Ctrl+K`、AI 意图栏 `Ctrl+I`、通知中心、任务中心

### 4.3 文件/项目层
- 首页（Backstage）：最近项目、模板（空白焊装站 / 空白总装站）、导入向导、示例。
- 项目内不再出现传统菜单栏；“文件”功能放在 Logo 菜单（Alt 可显示经典菜单，作为兼容选项）。

## 5. 布局与工作区

### 5.1 外壳结构（1920×1080 @100% 基准）

```
┌ 标题栏 44px：Logo/文件菜单 · 面包屑(项目›站点) · 【模式切换】 · 命令面板入口 · AI 状态 · 中/EN · 通知 · 窗口控制 ┐
├ 图标栏 46px ┬ 左面板 280–330px ┬────── 3D 视口（弹性） ───────┬ 右面板 330–400px ┤
│ (面板切换)   │ 装配树/操作/库    │  浮层：HUD、视图方块、工具条、  │ 属性检查器/AI 会话 │
│             │                  │  上下文工具栏、选择过滤器       │                  │
│             │                  ├─────── 底部面板 200–420px ─────┤                  │
│             │                  │ 时间线 / 甘特 / 信号 / 碰撞 / Python                │
└ 状态栏 26px：状态 · 性能 · 选择 · 光标坐标 · 单位 · 键位方案 · 联网状态（默认“本地·离线”） ┘
```

- 所有面板可停靠、浮动、拖到第二屏；Tab 化；可最小化成图标栏图标（类似 Figma UI3 的“最小化 UI” `Shift+\`，以及 `Ctrl+\` 全隐藏只留视口）。
- **布局与模式绑定**：每个模式记住自己的面板布局；用户修改后保存为“我的布局”，可重置为默认，可导出/导入 JSON（团队共享）。

### 5.2 六个任务模式

| 模式 | 快捷键 | 左面板 | 视口重点 | 右面板 | 底部面板 | 视口工具 |
|---|---|---|---|---|---|---|
| **建模** | 1 | 装配树、导入队列 | 几何、坐标系、测量、剖切 | 属性/变换、导入与简化设置 | 任务中心（导入/简化进度） | 移动/旋转/对齐/捕捉、测量、剖切、简化预览 |
| **运动学** | 2 | 运动链（树/图） | 按连杆着色、关节轴可视化 | 关节/连杆检查器、信号绑定 | 姿态表、耦合公式、运动学检查 | 拾取轴（两点/两圆心/面法向）、测试滑块 |
| **逻辑** | 3 | 块库、站内逻辑块列表 | 画中画 3D（跟随所选块的设备） | 块属性、真值/时序 | 问题、监视、执行轨迹 | 节点画布（中心区域替换视口） |
| **机器人** | 4 | 路径点表、程序、坐标系 | 路径（按速度着色）、TCP Gizmo、可达性 | 路径点/机器人检查器、点动 | 路径时间线（关节曲线、速度、外部轴、事件） | 示教、表面取点、配置翻转、可达性热图 |
| **调试** | 5 | 碰撞集、断点、快照 | 碰撞/近碰高亮、轨迹残影 | 事件详情、变量监视 | 时间线 + 事件日志 + Python 控制台 | 时间回溯（拖动播放头）、慢放、断点 |
| **虚拟调试** | 6 | 设备/信号树、连接 | 画中画或全屏 3D 联动 | 报警、强制、监视表 | 信号表 + 逻辑分析仪 | PLC 连接卡片、单周期、强制 |

模式切换规则：
- 切换动画 ≤ 180 ms（面板淡入/滑入），视口相机与选择**不变**；
- 模式只是“视图”，不锁定数据：在任何模式都能用 Ctrl+K 调出任何命令；
- 当用户在某模式下执行了属于另一个模式的命令（如在“机器人”模式里编辑关节限位），以检查器内联方式完成，不强制跳转；若需跳转，提示“在运动学模式中打开（2）”。

### 5.3 专注与演示
- **专注模式** `Ctrl+\`：隐藏所有面板，仅保留视口 + 播放条 + HUD。
- **演示模式** `F11`：全屏、隐藏编辑工具、显示节拍计数与标注，适合评审。
- **多屏**：可将“信号表 + 逻辑分析仪”整体拖到第二屏，作为“虚拟调试看板”。

## 6. 3D 视口

### 6.1 导航
- 默认：中键旋转 / Shift+中键平移 / 滚轮缩放（以光标为中心）；`F` 聚焦所选，`Home` 全部可见。
- 键位方案下拉：应点仿真默认 / PDPS 兼容 / NX 兼容 / Blender 风格（§16.3）。
- 相机书签 `Ctrl+Shift+1..9`；正交/透视 `5`；与视图方块联动。
- 3D 鼠标（3Dconnexion）支持。

### 6.2 视图方块（View Cube）
- 右上角，96×104 px，面/边/角均可点击（26 个方向）；面标签为中文“上/前/右”，英文切换后为 Top/Front/Right。
- 悬停高亮当前可点击区域；拖动方块 = 轨道旋转；右键：设为“前视图”、对齐到所选坐标系、对齐到机器人基座。

### 6.3 Gizmo（操纵器）
- 平移箭头 + 平面方块 + 旋转环 + 中心自由拖动；轴颜色 X 红 `#FF5C6C`、Y 绿 `#5FD38D`、Z 蓝 `#5B8CFF`（浅色主题略加深，见 §17）。
- 拖动时显示**数值气泡**（`ΔX +120.0 mm`），可直接键入数字并回车；`Ctrl` 吸附步长，`Shift` 精细。
- 参考系切换：世界 / 局部 / 父 / 自定义坐标系（Gizmo 旁小标签显示当前参考系）。
- 对机器人 TCP：拖动 Gizmo = 笛卡尔点动；超出可达范围时 Gizmo 变灰，并在末端显示红色虚影“不可达”。

### 6.4 测量
- 工具：点-点、点-面、边-边、最小距离（对象对对象）、角度、半径/直径、沿路径距离。
- 结果以青色 `#62D2F2` 标注线 + 胶囊标签悬浮；可“钉住”为持久标注（成为场景对象，可在评审中显示/隐藏）。
- 动态测量：可将测量绑定到两个运动对象，仿真时实时更新并画曲线（在时间线中作为一条轨道）。

### 6.5 HUD
左上角玻璃胶囊：视图模式（透视·着色+边线）· 仿真时间 · FPS · 三角面数。规则：
- 正常时低对比度；FPS < 30 时数值变黄并提示“建议开启 LOD”；
- 预览状态（AI 预览、路径预览）时 HUD 出现紫色标签“预览模式 · 场景未修改”。

### 6.6 上下文浮动工具栏
- 选中对象后，在对象附近（不遮挡对象包围盒）出现 1 行浮动工具栏，按对象类型给出 3–5 个最常用动作 + “…”；示例：
  - 机器人 TCP：示教点 / 关节点动 / 可达性 / …
  - 路径点：移到此点 / 之后插入 / 翻转配置 / …
  - 夹具：切换姿态 / 打开逻辑 / 信号 / …
- 出现延迟 120 ms，拖动相机时自动淡出；`Esc` 收起；位置随对象屏幕投影更新。

### 6.7 选择过滤器
- 左下角分段胶囊：组件 / 连杆 / 面 / 边 / 点 / 坐标系 / 路径点；单键 `Alt+1..7` 切换。
- `Tab` 在重叠对象间循环；`Alt+点击` 选父级；框选从左到右=完全包含，从右到左=相交（与 CAD 习惯一致）。
- 预选高亮：悬停时淡紫描边，选中时紫色发光描边 `--accent`（0 ~ 1 px 光晕，不影响模型本色）。

### 6.8 碰撞 / 近碰可视化
- 碰撞：红色 `--alarm` 实体高亮 + 接触点标记；近碰：琥珀色虚线圈 + 最小距离线 + 标签（“近碰 8.2 mm · R01 腕部 ↔ 侧围 B 柱 · 阈值 10 mm”）。
- 时间线上对应时刻出现琥珀/红色刻痕；点击刻痕 = 跳转到该时刻并聚焦。
- 碰撞集（谁对谁）在“调试”模式左面板管理；支持“仅显示当前问题对象”的隔离视图。

### 6.9 显示与性能
- 显示模式：着色 / 着色+边线 / 线框 / X 光 / 按连杆着色 / 按速度着色 / 按状态着色（ISA-101 灰阶，仅异常彩色）。
- LOD 与实例化状态在 HUD 弹出卡中可见；大装配加载时显示“渐进加载”环形进度，场景先显示包围盒。

## 7. 命令面板与 AI 意图栏（AI 原生层）

### 7.1 命令面板 `Ctrl+K`
- 居中浮层，宽 640 px；输入即模糊搜索（中文、拼音首字母、英文命令名都匹配，如 “sjd”“示教点”“Teach Target”）。
- 结果分组：**命令**（带快捷键提示）/ **对象**（场景中的机器人、路径点、信号…）/ **最近** / **帮助**。
- 支持“命令 + 参数”行内语法：`移动 E1 2460`、`>速度 W07..W12 200`；`@` 引用对象，`#` 引用信号，`/` 引用命令。
- 每条结果右侧显示快捷键，培养键盘习惯（Linear 模式）。
- 命令面板是 **命令注册表（Command Registry）** 的 UI；所有菜单、按钮、Python、AI 都调用同一注册表 → 天然可撤销、可录制、可脚本化。

### 7.2 AI 意图栏 `Ctrl+I`
**默认关闭**（设置 › AI › 启用本地助手）。关闭时：标题栏显示灰点“AI 已关闭”，Ctrl+I 打开说明卡与启用开关，不进行任何推理。

启用后的交互流程（见效果图 03）：

1. **意图输入**：视口底部中央的输入条（宽 900 px），支持 `@对象`、`#信号`、时间引用（“在 12.48 s 时”）；自动附带上下文胶囊（当前选择、当前时间、当前模式），用户可移除。
2. **意图理解卡**（右侧会话面板）：用结构化要点复述目标 / 约束 / 可调变量 / **不会修改的内容**。
3. **命令计划卡**：分步骤列出将执行的结构化命令（命令名 + 参数 + 预计影响），每步有状态（等待 / 运行 / 完成 / 失败）。
4. **沙盒预演**：计划在场景快照的副本中执行；3D 中以**幽灵叠加**（淡紫虚线轮廓）显示提议状态，原状态保持实体；右上角“预览对比”卡列出关键指标 前 → 后（J5 余量、最小距离、节拍）。
5. **为什么**：一行解释 + “查看依据”（展开可看求解候选数、约束是否满足、数据来源）。
6. **决策**：`应用全部 Ctrl+↵` / 逐步应用 / 编辑计划（计划变为可编辑表格） / 另存为 Python 脚本 / 取消 `Esc`。
7. **应用后**：作为**一个撤销组**进入撤销栈（`Ctrl+Z` 整体回滚）；活动记录中保留条目，可在任意时间回滚到此前检查点。

#### 风险分级与权限
| 级别 | 示例 | 默认策略 |
|---|---|---|
| R0 只读 | 查询、统计、解释、找对象 | 自动执行 |
| R1 可逆修改 | 路径参数、位置、姿态、命名 | 预览后确认 |
| R2 结构修改 | 新建/删除对象、修改运动链、修改信号映射 | 默认禁止，需在权限面板逐项开启，且必须逐步确认 |
| R3 外部影响 | 写 PLC、强制信号、联网、写文件到项目外 | 永久禁止 AI 直接执行；只能生成“待人工执行”的清单 |

- 权限面板（会话级/项目级）可视化显示上述策略；所有 AI 命令记录在**活动记录**（时间、命令、影响对象数、撤销按钮）。
- **本地优先**：推理在本机（本地模型或规则引擎）；状态栏常驻“本地 · 离线”。如果未来允许联网，需要显式开关 + 每次请求可审计，默认关闭。

#### 内联建议（非 AI 与 AI 区分）
- **规则检查**（确定性，不依赖 AI，始终可用）：如“J5 接近软限位”“W10 接近腕部奇异”，琥珀色卡片，带“预览/定位/忽略”。
- **AI 建议**（启用 AI 后）：使用**AI 墨水色**（`--ai-grad` 紫→青渐变描边/图标 ✦），绝不与报警色混用；`Tab` 接受、`Esc` 忽略（参考 Copilot Next Edit Suggestions 的“下一处编辑”提示，用于路径点批量修改等场景）。
- 视觉规则：AI 生成的一切（幽灵、路径、文本）都带 ✦ 标记或渐变，**用户总能分辨哪些是 AI 的提议**。

#### 失败与不确定
- 无解时：计划卡显示“无法同时满足：J5 ≥ 15° 与 近碰 ≥ 10 mm；最优折中为 …”，提供放宽约束的选项。
- 置信度低：显示“需要澄清”并给 2–3 个选项按钮，而不是猜测执行。
- 执行中可随时 `Esc` 中止；中止后沙盒丢弃，场景不受影响。

## 15. 通知与错误体验

| 类型 | 形态 | 何时用 | 持续 |
|---|---|---|---|
| 内联提示 | 字段下方小字 / 检查器卡片 | 输入非法、规则检查 | 直到修复 |
| Toast | 右下角，最多 3 个堆叠 | 操作完成、可撤销操作（含“撤销”按钮） | 5 s（可悬停暂停） |
| 状态栏消息 | 状态栏左侧 | 后台任务进度、连接状态 | 持续 |
| 问题面板 | 底部“问题”页签 | 逻辑/运动学/映射等结构问题 | 持续 |
| 报警 | 右侧报警卡 + 时间线刻痕 + 图标栏徽标 | 仿真/联调中的异常 | 直到确认 |
| 阻断对话框 | 模态 | **仅限**数据丢失风险（关闭未保存、覆盖文件） | — |

错误文案规范：**发生了什么 + 为什么 + 下一步**。例：“导入失败：BIW_SIDE_L.step 含 3 个非流形面（第 1 124、1 130、1 131 号）。可选择‘跳过这些面’或‘尝试修复’。” 错误码（如 `LB-201`）附在标题旁，可复制。

崩溃与恢复：自动保存（默认 3 分钟 + 每次 AI 应用前检查点）；启动时如检测到异常退出，提供“恢复到 12:31 的检查点”。

## 16. 可访问性、高 DPI 与快捷键

### 16.1 可访问性
- 文字对比度 ≥ 4.5:1（正文），≥ 3:1（大字与图标）；状态不只靠颜色（形状 + 文本 + 图标三重编码）。
- 色觉辅助：提供“红绿色弱”方案（X/Y/Z 轴改为 橙/青/蓝；报警红改为品红 + 图标）。
- 全键盘可达：焦点环 2 px `--accent`，偏移 2 px；面板间 `F6` 循环；树/表格方向键导航。

- UI 缩放：80%–200%（独立于系统 DPI），字号最小 11 px；动效可关闭（“减少动态效果”）。

- 图标全部使用 SVG（单色线性图标用 `currentColor` 着色），按设备像素比渲染缓存。
- 3D 视口以物理像素渲染（`devicePixelRatioF()`），叠加层线宽按逻辑像素；混合 DPI 多屏间拖动窗口时重建 FBO。

  - `e0` 平面：无阴影，依靠 1 px 线；

  | `motion.instant` | 80 ms | linear | 悬停、按下 |

## 19. Qt 实现说明

### 19.1 技术选型
| 区域 | 建议 | 理由 |
|---|---|---|
| 外壳、停靠、树、表格、检查器 | **Qt Widgets** + QSS（由令牌生成） | 桌面成熟、性能稳定、可访问性完善；大数据表格用 `QAbstractItemModel` + 自绘 delegate |
| 停靠系统 | **Qt Advanced Docking System (ADS)** | 支持 Tab 化、浮动、自动隐藏、透视布局保存；**许可证为 LGPL-2.1**：以动态库方式链接、保留版权声明、允许用户替换该库即可用于闭源私有软件；若修改 ADS 源码，修改部分需按 LGPL 提供 |
| 3D 视口 | `QOpenGLWidget`（或 `QWindow` + `createWindowContainer`）通过 `IRenderer` 抽象 | 未来可替换为 Vulkan/D3D12（Qt RHI）而不动 UI |
| 视口浮层（HUD、视图方块、上下文工具栏） | 优先**在渲染器内绘制**（ImGui 风格的即时模式叠加层，或 `QPainter` 在 GL 上绘制）；复杂浮层用无边框半透明 `QWidget` 子窗口 | 避免 `QQuickWidget` 的离屏渲染开销；与 3D 同帧刷新，无撕裂 |
| 节点编辑器 | `QGraphicsView`/`QGraphicsScene` 自研，或评估 QtNodes（需核实许可证与维护状态） | 需自定义端口类型、实时值气泡、子图；万级节点需 BSP 索引与 LOD（缩小时隐藏端口文字） |
| 时间线 / 曲线 / 甘特 | 自绘 `QWidget`（`QPainter` + 脏矩形）或 `QRhi` 自绘 | 关节曲线点数大，需降采样（LTTB）与 GPU 绘制选项 |
| 命令面板 / AI 计划卡 | Widgets 实现（无边框弹层 + 模糊背景截图） | 也可单独用 Qt Quick 窗口（`QQuickView` + `createWindowContainer`）获得流畅动画；不建议用 `QQuickWidget` 覆盖在 GL 视口上 |
| 首页/欢迎页、演示模式 | 可用 Qt Quick | 动画丰富、与核心编辑解耦 |

> 注意：同一顶层窗口中的 `QQuickWidget` 与 `QOpenGLWidget` 必须使用相同的图形 API；`QQuickWidget` 会增加一次离屏渲染并禁用线程化渲染（Qt 官方文档）。

### 19.2 线程与性能
- **UI 线程只做 UI**：渲染线程（或渲染在 UI 线程但仅提交 GPU 命令）、仿真线程（固定步长 4 ms）、碰撞线程池、导入/简化线程池、AI 推理进程（独立进程，崩溃不影响主程序）。
- 场景状态通过**不可变快照 + 增量**传递给 UI（例如每帧一个只读状态视图），避免锁竞争。
- 表格/树虚拟化（只创建可见行）；信号表 10 k 行、装配树 100 k 节点需保持 60 fps 滚动。
- 实时值刷新节流：UI 以 30 Hz 刷新信号值，波形缓冲环形队列；仿真/PLC 周期（4 ms）的数据全部保留在缓冲中供逻辑分析仪使用。
- 启动目标：冷启动 < 3 s 到首页；打开 1 GB 项目 < 15 s 可交互（渐进加载）。

### 19.3 命令系统（UI 与 AI 的共同基础）
- `CommandRegistry`：每个命令有 `id`、中英文名、拼音索引、参数 schema（JSON Schema）、风险等级、是否可撤销、帮助文本；
- 所有 UI 动作 = 命令调用 → 自动进入 `QUndoStack`（命令组 = 宏）→ 可录制为 Python；
- AI 层只能调用注册表中标记为 `ai_allowed` 的命令，参数先过 schema 校验；计划执行在**场景沙盒副本**中进行（写时复制），确认后重放到真实场景。

### 19.4 QSS 与样式注意事项
- QSS 不支持变量：用构建脚本把 `tokens.json` 编译成 QSS；主题切换时重新 `setStyleSheet` 根样式（或使用 `QPalette` + 自定义 `QProxyStyle` 绘制关键控件，性能更好）。
- 复杂控件（限位条、类型端口、玻璃浮层）用自绘，不靠 QSS。
- Windows 11：标题栏使用无边框窗口 + 自绘（`QWindowKit` 等方案，需核实许可证）或保留系统标题栏 + 深色模式 DWM 属性，权衡可靠性。

### 19.5 国际化
- `tr()` + `.ts`；中文为源语言或英文为源语言均可，但**命令 id 与 Python API 始终英文**；
- 切换语言实时生效（`QEvent::LanguageChange`）；命令面板同时索引中英文名，切换语言后旧习惯仍可搜到。
- 中文字号比英文同等级视觉偏大，组件高度按中文校准，英文时不缩小控件。
