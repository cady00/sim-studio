# 局限与未实现路径

这份清单来自一次全仓检索：空函数体、`TODO` / `FIXME`、`not implemented`、`placeholder`、导入器直接失败、以及会把通用数字当成数据表的路径。能接上真实行为的已经接上。其余条目保持失败或明确拒绝，不返回假数据。

## 这次补上的空路径

- `MainWindow::runScriptSnippet` 原先是空函数，脚本停靠栏也没有入口。现在「运行片段」把编辑器里的源码交给 `IScriptHost::execute`，标准输出和异常写进脚本日志。场景里还没有脚本时会先建一条名为 `snippet` 的脚本。
- 运动学面板「建议连杆」原先对每根关节都套 `RevoluteLimit` 的缺省值（±180°、90°/s）。资源名包含 `kr420` 且建议出 6 个转动关节时，改为 `kr420DatasheetLimits()`（A1–A6 的公开行程和速度，见 `docs/KR420.md`）。

## 保持失败，不伪装成功

| 路径 | 实际行为 |
| --- | --- |
| JT（`JtImporter`） | 按公开的 ISO 14306 布局自写，不链接 Siemens JT Open Toolkit，也不使用 GPL/LGPL 的 JT 库。能读 8.x/9.x/10.x 的文件头、TOC 和段，zlib 与 XZ/LZMA 段，LSG 装配、几何变换和材质。量化 Tri-Strip（Null、半字节 Bitlength、Deering）和 JT 9 拓扑压缩网格都能出三角形：算术编码、6 比特 Bitlength、Chopper、Lag1/Lag2/Stride/StripIndex/Ramp/Xor，以及无损或均匀量化的顶点、Deering 或无损法向。公开预测器表里没有几何 “moving frame”，没有另造一个。第一代 Huffman/前缀 Bitlength 有解码和测试，这三份样件不用它。无损坐标的存储哈希对不上重建后的 IEEE 字，改用量化盒范围和单位法向核对；量化码的哈希必须相符。JT 10.5 的 Tri-Strip 在绑定之后多了一段公开参考里没有的 GUID 本地头，后续字节也不是已发布的 Int32 包，`boxasm.jt` 只显示装配，不造三角形。XT B-rep 仍跳过 Parasolid 字节。没有单位字符串的文件保持文件单位（螺钉和 CTC 样件是米）。 |
| IGES | `createImporter("iges")` 和资源注册表都走 OCCT `IGESControl_Reader`，读入后做三角化。读失败时返回错误，不造网格。 |
| 二进制 DXF | 读到二进制头时返回 `binary DXF is not supported`。 |
| 压缩 ZIP | 工程包只接受存储法（method 0）。压缩条目报错，不假装解压成功。 |
| `nl_to_logic`、`layout_suggest`、`cycle_optimize`、`explain_anomaly` | 默认用离线规则生成命令，再交给 `CommandExecutor`。改动进撤销栈。句子对不上规则时仍给出一条明确的缺省命令，不假装听懂了。 |
| AI 提供方 | 默认关闭，不打开套接字。启用后只接受 `http://127.0.0.1` 或 `http://localhost` 的 OpenAI 兼容 `POST /v1/chat/completions`。其它主机直接拒绝。连不上本机时退回规则。`usesNetwork()` 保持为假，因为没有出本机的请求。 |
| `IRcsAdapter` | 只有纯虚接口，没有厂商 RCS 实现。规划走内置求解器。 |
| PLCSIM Advanced | 卡片只显示地址和「本机没有安装运行时」。不打开套接字。 |
| OPC UA 互通 | 自研客户端只和本仓库的回环服务器对测。没有 open62541 互通，也没有 PLCSIM 连接。 |
| 通用 PPR / eMS XML | 读写操作、资源、零件、焊点、路径和位置（欧拉角 XYZ，度）。元素名按公开课程和接口里能见到的叫法匹配，例如 Operation、Resource、Part、WeldPoint、RobotPath、Location。认不出的元素连同原文写回。这不是某家软件的完整 eBOP 模式，也不解析 `.ppj` / `.ppd`。 |

## 算法和数据用了简化，调用方看得到边界

- 建议连杆不再写 180°/s²。没有扭矩和惯量时，加速度来源是速度限制，节拍只受 `maxSpeed` 约束。非 KR420 的建议限位仍是 ±180°、90°/s。资源名含 `kr420` 且建议出 6 个转动关节时，行程和速度用公开数据表。用户输入的加速度来源标成「用户」；有扭矩、质量和负载时标成「动力学」，并按负载折减。
- 同一 STEP 里离关节轴较远的零件不会被收进这台机器人（径向超过 600 mm 和 5 倍圆柱半径中的较大值）。第二台机器留在原地。
- 焊点可达性把打开文件时已经相交的零件对当成装配接触。新的相交要深过 2 mm 才把该焊点标成碰撞。分组轴和真实转轴不完全重合时，大角度仍会报碰撞。
- `addKr420TrackDemonstration` 里滑台的速度和加速度是 1500 mm/s 与 1500 mm/s²。公开 KL 数据表没有用在这两个数上，源码注释已标明。
- DXF：直线、圆弧、圆、多段线、均匀三次样条、三维面、椭圆。填充按图案线（角度、基点、偏移、虚线）裁到边界里；实心填充没有图案线时用平行线铺满。尺寸有尺寸线、箭头和用笔画出来的文字。INSERT 会递归展开块里的块。
- glTF：图元上的形态目标按节点或网格的权重加进顶点。权重为 0 时形状不变。
- URDF：`package://包名/路径` 会在 URDF 所在目录、它的上一级，以及 `ROS_PACKAGE_PATH` 和 `SIM_PACKAGE_PATH`（冒号分隔）里查找。网格按米读入后再乘 1000 和缩放，变成毫米。找不到文件时这条网格失败，不造一个假零件。
- 图像嵌入是 ZIP 里的字节，不是 GIS。
- 焊点自旋搜索不对每个转角做碰撞，只在选中的姿态上做一次接近检查。修正建议是一次正逆解试探。
- 连杆包络是网格包围盒角点沿关节样本（步长不超过 20°）的凸包。没有连杆网格时，球腕模型用四段解析臂杆。不是三角面沿螺旋运动的连续扫掠。
- 避障是关节空间双向 RRT。直线段已无碰撞时结果就是起点和终点。连接失败会退回直线段。
- KUKA：有 PTP、LIN、SPL、SLIN、SPLINE / ENDSPLINE、`$TOOL` / `$BASE`（XYZABC）、INTERRUPT 和 IO。没有完整 BAS，没有工具标定数据。中断文本会保存并再次写出，仿真不执行中断程序。`$VEL_AXIS` 不作为指令往返。
- ABB：`confdata` 置零，未使用的外部轴写成 `9E9`。
- FANUC：只有 ASCII LS，没有二进制 TP。
- 齿轮、凸轮、电子凸轮、位置/速度控制器、限位、气缸、抓手、发生器和收集器只在内置求解器里积分。Jolt 不跑这些装置。
- Jolt 没有沿曲面骑行，网格碰撞体是凸包。网格对网格、连续碰撞和多点接触在内置求解器里。没有重写 Jolt 的 CCD。
- 机器人目录有 KR6_R900、IRB120、LRMate200iD、GP8 四条。限位、速度和连杆原点抄自 `docs/ROBOTS.md` 里的公开页面，资源的 `source` 写着链接，待用户核实。LR Mate 的 J3 在 xacro 里是 −70° 到 +205°，产品页写的行程是 420°。这四条没有公开的关节扭矩和连杆惯量，加速度来源是速度限制，不是 180°/s²。连杆网格是 ROS-Industrial 的 STL，包许可证没有单独的网格再分发说明，所以不入库；首次使用下载到 `~/.local/share/SimStudio/catalog-meshes`，`SIM_CATALOG_MESH_DIR` 只读本地目录，`SIM_CATALOG_MESH_OFFLINE=1` 不访问网络。下载失败的连杆仍是方盒。没有找到 KR 280 R3080 的公开网格，双机演示里第二台仍是橙色方盒，用户可以自己导入 STEP。导入 URDF 或 xacro 时，若关节写了 `effort` 且连杆写了质量，加速度改由扭矩和惯量估算，网格随视觉节点进入机器人资源。
- 序列编辑器用操作树旁边的时间轴画工序，过渡把后一道工序推迟到前一道结束加延迟，信号事件可以在工序开始或结束置位，另一道工序可以等这个信号。欢迎页的「打开示例工程」装入 IRB 120 焊装单元（布局、焊点、路径、夹具、`part_seen` / `weld_done` / `clamp`、节拍），不用 KR 420 的 STEP。
- 示波器在仿真步进之后记下勾选的信号和关节指令，横轴是仿真时间。关节速度和加速度是相邻采样的后向差分，第一步记 0。游标读的是该时刻之前最近的一个采样。导出的 CSV 第一列是时间，关节列可以带 `.v` 和 `.a`。轨迹最多保留 240000 行。它不记录网格接触力。
- 运动学页的关节滑块按当前关节的下限和上限拖动位置，松手之前就作用到连杆。视口拾取选中包含该零件的最内层连杆，以及以它为子连杆的关节。姿态库列出当前机构已记录的姿态，记录和运动到姿态读写同一份列表。`--demo devices` 里的转台、滚床和升降机只通过 `ensureResource`、`addLink`、`adoptParts`、`addJoint` 和 `capturePose` 搭出来。
- 逻辑图画布可以拖动节点，位置记在块的 `pins` 里。从输出块右侧拖到另一块的输入，两边会共享同一个信号名。双击步骤可改动作。画布上的文本和运动学页的 Python、动作列表读写同一份逻辑块。仿真时当前步骤以及为真的输入输出信号用琥珀色描边。
- 甘特图拖动色条不建立前后约束。
- OPC UA Basic256Sha256 的对称 IV 是每条消息明文前置的 16 字节随机数。证书是 RSA-2048 自签。
- 撤销和重做记录结构与变换通知：属性、焊点、产线、信号、运动学和意图命令。意图条里的一批命令记成一步。快捷键是 Ctrl+Z 和 Ctrl+Y（文本框仍用控件自己的撤销）。仿真播放期间不记栈，选择变化也不进栈。栈深 16，每步是一份工程快照。运行中生成的临时克隆不写进快照。
- 导入器对空文件、截断文件和随机字节返回错误。二进制 STL 如果声明的三角形个数超过文件剩余字节，直接拒绝，不会按那个个数分配内存。OBJ 里无法解析的顶点序号记成 0，不把异常抛出进程。glTF 和注册表入口把解析异常收成错误字符串。
- 工程在运行中每 45 秒把脏场景写到应用数据目录的 `recovery/autosave.simproj`，并记下进程号。正常退出会清掉这次会话。下次启动时如果进程号已经不在，就载入那份自动保存。
- 普通构建全量测试：134 个用例、3334 条断言，通过。ASan 加 UBSan（关闭了 vptr 检查，因为预编译的 Jolt 没有匹配的 typeinfo）用 `quarantine_size_mb=0` 跑同一套：134 个用例、3334 条断言，没有 AddressSanitizer 或 UndefinedBehaviorSanitizer 的中止。LeakSanitizer 剩下 120608 字节、1743 次分配，栈在 Open CASCADE 的 STEP/IGES 协议表和 pybind11 的类型对象里，是这两座库第一次用到时建的静态表。原先约 26 MB 的泄漏来自我们自己留下的进程级对象：STEP 的 XCAF 文档交给 `XCAFApp_Application` 之后没有 `Close`，Jolt 的 `Factory` 没有释放，内嵌的 CPython 没有 `finalize`。这三处都在进程退出前关掉。
- 逻辑块可以设 `repeat`，走完最后一步就从第一步再来。示例线的三块逻辑都开了循环。工序表用 `layout.cyclic` 表示节拍可以一单一单接下去。发生器按 `interval` 往唯一的入口槽投料；槽被占着的时间记成发生器阻塞。工位有料且在加工是忙，加工完但下一工位还占着是阻塞，没有料是饥饿。产量是离开最后工位的件数，JPH 是产量除以仿真小时。示例线跑 3600 s 的离散节拍：产量 297，JPH 297，焊接工位利用率 99.6%，饥饿 16 s（开头爬坡），阻塞 0，发生器阻塞 1192 s（投料间隔 8 s，瓶颈是焊接 12 s）。甘特图「连续生产」用的就是这套离散推演，文案以「估算」开头，并写出投料间隔、各工位占用和每个工序秒数的来源（工序表、路径规划、逻辑步进、传感器、输送或钉住）。它不含网格碰撞，也不是下面 KR420 一小时接触计数。测算节拍若把焊接从工序表的 12 s 改成路径规划秒数，JPH 会变，界面会标成路径规划。
- 示例焊装线用内置求解器按 60 Hz 走完 3600 s 时，发生器的原型被清掉，避免一小时里堆出几百个克隆。这次全量套件里测得墙钟 1.183 s，实时倍率 3042。RSS 起止都是 217588 KB。节点保持 10（四个工位上的装置，加上料坯模板、发生器和收集器）。这组数没有 KR420 网格。RSS 绝对值含套件里此前已加载的库，起止差是 0。
- KR420 STEP 分组之后，每根连杆取三角面最多的那个零件，共 7 个真实网格碰撞体。腕部网格中心放一个不休眠的盒子，每个物理步都把它放回当前网格里，所以接触来自网格而不是代理方盒。发生器在机器人旁边按 12 s 投料，收集器收下。同一条线再跑离散节拍。手臂现在沿直线走到逆解，不再在不可达处停住关节。内置求解器 60 Hz 走完 3600 s：墙钟 38.65 s，实时倍率 93.1。186751 个物理步产生了接触，接触次数合计 594022。产量 299，JPH 299，收集器计数 300。节点保持 180。RSS 起止都是 219656 KB。
- KR420 示范路径 `cycle` 合计 3.200 s。三段未混合时长是 0.017 s（home）、0.283 s（away）、2.967 s（return），相加 3.267 s。过渡区叠掉 4 帧（0.067 s）之后，与 193 个采样、步长 1/60 s 的节拍一致。最长的一段是 `return`：从离开位回到原点的直线，长 540 mm，速度 200 mm/s。点到点段不再受 180°/s² 占位加速度限制，所以总秒数比占位还在时的 3.52 s 短。这条直线两端都是合法关节角的正解，不碰限位，也不出分组后的工作空间。原先数值逆解在位置已经对齐（约 0.0001 mm）后，把 0.05°–0.17° 的姿态残差报成 `unreachable`，因为毫米和弧度混在同一个法方程里，姿态行被淹没，失败时还留下最后一次迭代而不是最好的一次。逆解现在在位置进入 1 mm 后把姿态行按 1000 mm/rad 对齐，并保留最好的迭代。页脚显示「规划完成」。焊装巡回 `weld_tour` 同样没有 `unreachable`：四段未混合时长 0.017 s、0.017 s、2.967 s、2.967 s，合计与节拍同为 5.967 s。
- 十万零件压测（llvmpipe、MSAA 4、1440×900）：提交 10 万实例、2560 万三角形时整帧约 2938 ms（0.34 fps），RSS 约 1156 MB；近处视锥后约 81 ms（12.3 fps）。平铺场的软件遮挡是 0；贴墙擦过遮挡 17877。GPU 视锥剔除是一次 430 路计算调度，不是每帧路径。
- 不生成 Windows 安装包。KR420 STEP 留在 `testdata/local/`，不进版本库。
